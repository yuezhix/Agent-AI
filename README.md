# Agent AI

Agent AI is a document question-answering web application. Users upload PDF files, pick a document, and ask questions by typing or by voice. Every question gets two answers side by side: one from the selected PDF using retrieval-augmented generation (RAG), and one from a live web search that runs through a Model Context Protocol (MCP) server.

The frontend is built with React and Ant Design. The backend is a Node.js Express server that uses LangChain and OpenAI for the document answer, and an MCP client and server that wrap SerpAPI Google search for the web answer. Each PDF is indexed once when it is uploaded, and the index is saved to disk so it is not rebuilt after a restart.

## Features

- PDF upload with file type and size checks, one document ID per file
- One-time indexing at upload: the text is split into 500-character chunks, embedded with OpenAI, and saved to disk
- Document list and selector: questions only search the selected document
- Document answer generated by GPT-5 from the most relevant chunks
- Web answer from an MCP `search_web` tool backed by SerpAPI, summarized by GPT-5
- Both answers requested in parallel with a 60-second timeout each; if one fails, the other is still shown, and the failed side shows its error
- Voice mode: spoken questions are submitted automatically, the document answer is read aloud, and the app starts listening again
- Backend tests with the Node.js test runner, frontend tests with Jest and React Testing Library

## Architecture

```
Browser (React)
  ├── Web Speech API                 speech recognition and text-to-speech
  └── Express server (Node.js)       JSON and multipart requests
        ├── docStore                 document list and vector indexes (memory + JSON files)
        ├── RAG (LangChain)   ─────→ OpenAI API: embeddings, GPT-5
        └── MCP client  ─ stdio ─→ MCP server ─→ SerpAPI (Google Search)
```

When a PDF is uploaded, the server saves it under a new UUID, builds the vector index, and writes the index to `server/data/indexes/<id>.json`. For each question, `/chat` starts the RAG task and the web search task at the same time and waits for both with `Promise.allSettled`. The response carries `ragAnswer`, `ragError`, `mcpAnswer`, and `mcpError`, so the frontend can show each answer or its error separately.

## Project Structure

| Path | Responsibility |
| --- | --- |
| `src/App.js` | Holds the conversation, loading state, document list, and selected document. |
| `src/api.js` | Sends upload, document list, and chat requests; turns request failures into answer errors. |
| `src/components/PdfUploader.js` | Checks that files are PDFs and uploads them. |
| `src/components/DocumentSelector.js` | Lists uploaded documents and switches the selected one. |
| `src/components/ChatComponent.js` | Text questions, Chat Mode, speech recognition, and text-to-speech. |
| `src/components/RenderQA.js` | Shows each question with the document answer and web answer, or their errors. |
| `server/server.js` | Loads environment variables, creates the document store, and starts the server on port 5001. |
| `server/app.js` | Express routes, upload rules, input checks, timeouts, and error responses. |
| `server/docStore.js` | Keeps document metadata and indexes in memory, saves them to disk, and restores them. |
| `server/chat.js` | Builds, saves, and restores the PDF index, and answers from the retrieved chunks. |
| `server/chat-mcp.js` | Starts the MCP client, calls `search_web`, and summarizes the results. |
| `server/mcp-server.js` | MCP server that exposes SerpAPI search as the `search_web` tool. |
| `server/test/` | Backend tests with fake index and answer functions. |

## API

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/documents` | List uploaded documents, newest first |
| POST | `/upload` | Upload a PDF as multipart form data (`file`), build its index, and return the document |
| GET | `/chat?question=...&documentId=...` | Return the document answer and the web answer |

`/chat` returns `400` when the question is empty, `404` when the document does not exist, and `502` when both answers fail. If only one answer fails, it returns `200` with the error in `ragError` or `mcpError`.

## Run Locally

Requirements:

- Node.js 22 or later
- An OpenAI API key
- A SerpAPI key
- Chrome, for voice mode

Install dependencies:

```bash
npm install
cd server && npm install
```

Create `server/.env` (see `server/.env.example`):

```
OPENAI_API_KEY=your_openai_api_key
SERPAPI_KEY=your_serpapi_key
```

Start the frontend and backend together from the project root:

```bash
npm run dev
```

Open http://localhost:3000. In development, the React dev server forwards API requests to the backend on port 5001 through the `proxy` setting in `package.json`.

## Test

Frontend:

```bash
CI=true npm test -- --watchAll=false
```

Backend:

```bash
cd server && npm test
```

The backend tests use fake index and answer functions, so they do not call OpenAI or SerpAPI.

## Configuration

| Name | Where | Description |
| --- | --- | --- |
| `OPENAI_API_KEY` | `server/.env` | OpenAI API key for embeddings and answers |
| `SERPAPI_KEY` | `server/.env` | SerpAPI key for the MCP search tool |
| `PORT` | `server/.env` | Backend port, default `5001` |
| `REACT_APP_API_URL` | frontend environment | Backend URL; overrides the development proxy |

`server/.env` and all other `.env` files are ignored by Git. Uploaded files and saved indexes in `server/uploads/` and `server/data/` are ignored as well.

## Current Scope

This is a learning project that runs locally. Documents cannot be deleted from the UI yet, conversation history stays in the browser and is not sent to the backend, and answers do not include PDF page numbers or web links. The web search prompt summarizes the search results without the original question, so web answers can be general. The API has no authentication or per-user isolation, and CORS allows all origins.
